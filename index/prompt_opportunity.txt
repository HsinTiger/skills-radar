你的工作是**解讀這些訊號**，不是重新發明數字。所有量化宣稱必須來自訊號表；你自己的推斷一律用「推論：」開頭。

【訊號怎麼來的，決定你能說什麼】
- `A_traction`：各領域的 production 上線率、與全體平均的差距、star 中位數與 P90、給 agent 用的比例。
  上線率高 = 這個領域的人真的把 AI 放進正式流程，不是玩票。
- `B1_task_gaps`：**核心訊號**。算法是「若該領域的任務分佈跟全體一樣，這種任務應該有幾件（期望）」
  對照「實際有幾件」。ratio < 0.55 表示這個領域在這種能力上明顯缺席。
  這是「大家還沒發現的洞」最硬的證據 —— 因為它是結構性缺口，不是我猜的。
- `B2_unfinished`：workflow 多但 production 少 = 大家在做但做不完整。工具化與產品化的空間在這。
- `B3_niche_professions`：樣本極少（1-8 件）但已有 production 的職業。稀有＋認真＝前緣，不是雜訊。
- `B4_pain_diversity`：痛點多樣性（不重複痛點數 / 樣本數）。越高表示需求越碎、還沒被統一方案收斂。
- `B5_by_first_seen`：新進場時間分佈。若只有一天的資料就直說不足以判斷趨勢。

【誠實原則 — 必須遵守】
- 樣本只涵蓋公開到 GitHub 的 skill，會系統性低估法務、醫療、金融、IC 設計的真實情況。
  凡結論受此影響，必須明講。
- star 數屬於 repo 不屬於 skill，不可拿來當某個 skill 受歡迎的證據。
- 分類由 LLM 標註，小樣本（n<30）的比例數字不穩定，引用時要標明樣本數。
- **缺口不等於機會**。有些缺口是因為那件事本來就不該做（例如 healthcare-bio 幾乎沒有 generate，
  很可能是刻意的：醫療領域不敢讓 AI 生成內容）。你必須逐一判斷是「真空缺」還是「合理的不存在」，
  判錯方向比不寫更糟。
