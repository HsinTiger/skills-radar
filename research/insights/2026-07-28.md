# AI 洞察專區 — 2026-07-28

## 一句話判斷
security 和 devops-infra 拿到最漂亮的文件 proxy，但可能是「安全意識強、寫得清楚」造成的敘事優勢；hardware-eda（你的本業）樣本小到近乎統計雜訊，卻同時是 pain diversity 最高、完成率倒數第三——這只能提出「公開供給稀薄且 IC 設計被系統性低估」的假說，還不能證明市場需求。

## 二、沒人發現的機會

### 結構性缺口（B1）

- **healthcare-bio × generate（ratio 0.04）**：真空缺，但**判定為合理不存在**。醫療內容生成有法律責任問題，作者不敢標「AI 生成」很正常。不要碰生成，但 verify/analyze 類（審查、比對、稽核）沒有這個心理障礙——那才是機會。
- **personal-productivity × verify（ratio 0.07）**：公開供給缺口，可形成機會假說。個人生產力工具多在「幫你做事」，少有「幫你檢查有沒有做對」。最小驗證：把你自己的 pipeline 稽核習慣（規格+驗收）包裝成「個人任務驗收 skill」，觀察是否有人重複使用；在此之前不能稱為需求已驗證。
- **finance-investing × transform（ratio 0.14）**：公開供給缺口，可形成機會假說。金融 skill 多是分析報告、算比率，較少「格式轉換」（報表格式互轉、跨資料源標準化）。潛在付費者假說是獨立投資人或小型 RIA；最小驗證是財報或持倉 CSV → 統一 schema 的研究工具，且不得接觸交易 credential。
- **security × orchestrate（ratio 0.15）**：真空缺，但要小心——安全工具本來就抗拒「自動串接執行」，怕誤觸生產環境。判定：半真空，機會在「唯讀式編排」（多工具掃描結果彙整），不是「自動修復編排」。
- **design-creative × analyze（ratio 0.17）**：公開供給缺口，可形成機會假說。設計領域較少「分析既有設計或素材」的 skill。潛在付費者假說是需要大量素材規範稽核的品牌方；最小驗證是素材風格或合規稽核 skill。
- **writing-content × configure/orchestrate（ratio 0.18/0.19）**：合理偏真空——寫作類工具通常單點操作（潤稿、生成），沒有「設定管線、多步驟編排」的需求，因為個人寫作者不需要複雜配置。不建議優先做。

### 做一半的領域（B2）

- **education-training（完成率 0.19）**：workflow 54 件、production 只 13 件。卡點大概是「教學內容需要客製化到每個班級/課程」，通用 skill 做不到最後一哩路。做工具的切入點：不是做「教材生成器」，是做「教材生成後的品質檢查層」。
- **personal-productivity（完成率 0.24）**：210 件 workflow 中有 65 件標示 production，表示公開工作流供給已存在，但不等於付費需求已驗證。可能卡在標準化——每個人的生產力習慣都不同，通用方案很難達到 production 等級。可驗證的方向是「框架而非成品」：提供客製化骨架，而不是宣稱一套方案適用所有人。
- **research-academia（完成率 0.29）**：126 件 workflow、51 件 production。卡點通常是文獻/資料來源的授權與可信度驗證，做完的門檻卡在「引用要對」。

### 前緣職業（B3）

- **逆向工程師（n=7, production 6）**：文件標示 production 比例高。痛點「閉源執行檔黑箱逆向耗時」可形成小眾市場假說，但 GitHub 語料不能驗證市場規模或付費意願。
- **教會法律師（n=5, production 5）**：樣本全數標示 production，但極小樣本不能證明普遍成熟。推論：垂直到夠窄、規則夠明確的領域可能較容易形成完整 skill；你的 baseband IC 設計知識庫可用同樣的封閉規則集假說做實驗。
- **資安檢測員（n=4, production 4）**：max_stars 只有 5，樣本也全數標示 production。這只是「repo stars 低仍可能有完整文件」的反例，不足以證明兩者統計上無關。
- **財務分析師（n=6, production 4）**：痛點「多版本分類帳查詢」、「財務比率手動計算」可形成產業痛點假說；目前只能說值得訪談驗證，不能說市場已被驗證或尚未被服務。

## 三、短期看法（一個月內）

1. 立刻可做：把你既有的「規格+驗收」工作流包裝成 personal-productivity × verify 的 skill，B1 訊號顯示這格幾乎是零（ratio 0.07），你本來就在做這件事，成本最低。
2. finance-investing × transform 的缺口可以拿來測試你的 Substack 選題：寫一篇「為什麼金融 AI 工具全是分析器，沒人做轉換器」，直接引用 B1 數字。
3. 不要碰 healthcare-bio 的 generate 缺口——先花五分鐘確認自己沒有被「缺口=機會」的直覺誤導，這格是本報告裡最容易判斷錯的地雷。

## 四、中期看法（一季內）

1. 賭 hardware-eda（n=36 太小，不下重注但值得種）：completion_ratio 0.37、diversity 1.0，公開語料嚴重低估這塊，因為 IC 設計圈根本不習慣把工具公開發 GitHub。我賭這塊會慢慢冒出頭，尤其你自己就是活生生的反例（一個 IC 工程師在自建 pipeline 卻不會出現在這份語料裡）。**什麼訊號證明我錯**：如果三個月後 hardware-eda 樣本數沒有明顯成長、且新增樣本依然全是 EDA 工具腳本而非設計流程類，就代表這領域真的不會走向公開化，我的判斷錯。
2. 賭 education-training 的完成率會持續墊底（目前 0.19 最低），因為教育的客製化本質跟通用 skill 天生衝突，不是暫時性缺口。**反證訊號**：如果下季 completion_ratio 明顯回升到 0.3+，代表有人找到了「模板化教育內容」的解法，我要重新評估。

## 五、對讀者的具體意涵

1. 你的技術知識庫 pipeline 可以參考「教會法律師」模式——窄範圍、封閉規則集，比廣泛通用的知識庫更容易做到 production 等級完成度。
2. 市場監控 pipeline 可補一個 finance-investing×transform 模組（資料格式標準化），這是訊號表裡少數「誰付錢」很清楚（獨立投資人）又幾乎零供給的格子。
3. Substack 非共識題材，HOOK：**「Star 數是騙人的」**——用資安檢測員（max_stars=5、樣本全數標示 production）跟 legal-compliance（agent_facing 僅1.1%卻標高 production）提出「熱門不等於文件完整」的反例；不要升格成因果結論。

## 訊號可信度

- **樣本內可重算**：B1 task gap 與 B2 completion_ratio 的算式可重現；但輸入仍來自公開 GitHub 樣本與 LLM 分類 proxy，不能說不受敘事或抽樣偏誤影響。
- **只是初步跡象**：B3 全部——n 都在 3-8 之間，任何一個比例都可能因為 1 件樣本改變而翻倍。逆向工程師/教會法律師的結論僅供方向參考，不能拿來做投資決策。
- **樣本嚴重不足**：hardware-eda 全部訊號（n=36）、B5 只有一天資料完全無法判斷趨勢，本報告的中期判斷 1 是基於直覺推論加上樣本外知識，不是這份訊號表本身能撐起的結論，我已明確標注「推論」。
- **系統性偏誤要記住**：healthcare-bio、legal-compliance、hardware-eda（你的本業）都是本報告開頭就講明「會被低估」的領域，任何看似「小」的結論都可能只是「GitHub 上看不到」而不是「真的小」。
