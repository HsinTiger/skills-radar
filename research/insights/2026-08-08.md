# AI 洞察專區 — 2026-08-08

## 一句話判斷
AI Agent 的落地已跨越「生成」階段，正在往「高規格審查（Verify）」與「繁瑣配置（Configure）」的企業痛點收斂，但多數領域缺乏能串接既有工作流的最後一哩路。

## 一、已經拿到成績的領域

以下領域的 Agent 不僅停留在測試，而是真正進入了 Production（正式流程）。

## 二、沒人發現的機會

### 結構性缺口（B1）

從任務分佈對比全體平均，以下是明顯缺席的領域。

1. **sales-crm 的 verify（預期 23.9，實際 1，Ratio 0.04）**
   * **判斷：真空缺 ＝ 巨大機會。** CRM 系統裡充滿業務隨手填寫的髒資料。
   * **誰會付錢：** 銷售營運（SalesOps）主管。
   * **最小可行做法：** 寫一個輕量腳本，每天抓取新建立的 CRM 紀錄，用 AI 驗證統編、地址、公司名稱是否與公開商業司資料庫吻合，不符就自動標記。

2. **legal-compliance 的 orchestrate（預期 48.2，實際 2，Ratio 0.04）**
   * **判斷：合理不存在 ＝ 不要碰。** 
   * **原因：** 法務流程的容錯率極低。如果讓 AI Agent 擁有 Orchestrate（調度與決策）權限去自動發送存證信函或修改合約，一旦出錯將面臨嚴重法律責任。人類必須保留在迴圈內（Human-in-the-loop）。

3. **design-creative 的 configure（預期 364.9，實際 28，Ratio 0.08）**
   * **判斷：真空缺 ＝ 機會。** 設計師花大量時間在對齊品牌色票、字體、版型等「配置」工作，但目前 AI 多集中在「生成（Generate）」。
   * **誰會付錢：** 品牌行銷團隊、設計系統維護者。
   * **最小可行做法：** 建立一個能將 Figma Design Tokens 自動轉譯並配置到各類 AI 繪圖提示詞（Prompt）或前端 CSS 框架中的 Agent Skill。

4. **security 的 transform（預期 137.8，實際 11，Ratio 0.08）**
   * **判斷：真空缺 ＝ 機會。** 資安日誌格式（Syslog, JSON, CEF）極其混亂，但現在大家多把 AI 拿來做偵測（Analyze），少用來做格式正規化。
   * **誰會付錢：** 資安託管服務商（MSSP）、DevSecOps 團隊。
   * **最小可行做法：** 開發一個能吃任意格式安全設備日誌，並自動轉換成標準開源 schema（如 OCSF）的解析器 Agent。

### 做一半的領域（B2）

這些領域的工作流（Workflow）很多，但轉化為 Production 的比例極低。需求已驗證，但卡在落地。

1. **sales-crm (完成率 0.20，樣本 130)**
   * **卡關原因：** 信任度與寫入權限。讀取 CRM 資料做報表容易，但要 AI 自動更新客戶狀態或推進銷售階段，業務員不敢放權。需要建立極強的「操作前審核（Approval）」機制。
2. **hardware-eda (完成率 0.25，樣本 996)**
   * **卡關原因：** 封閉生態系。EDA 工具（如 Synopsys, Cadence）多為重度 GUI 依賴或有獨有的古老 CLI 語法（Tcl）。Agent 難以直接操作這些封閉系統。這正是你的主場。

### 前緣職業（B3）

少數先鋒者已在正式環境使用的痛點，這些痛點往往是該行業尚未被標準 SaaS 滿足的共通需求。

1. **視覺設計師 (AI 圖片生成提示詞控制困難且風格難一致)**
   * **普遍性：** 極高。品牌一致性是所有 B2B/B2C 企業的剛需。
   * **洞察：** 解決「控制力」與「一致性」的工具，比單純追求生成畫質的工具更有商業價值。
2. **資安顧問 (手動進行符合 NIST 規範的資安風險評估耗時)**
   * **普遍性：** 極高。合規是企業的剛性成本。
   * **洞察：** 將厚重的合規框架（NIST, ISO27001）拆解成 Agent 可以一條一條比對的 Check-list Skill，是極佳的 B2B 題目。
3. **教會法律師 (天主教法典條文檢索與審查架構複雜)**
   * **普遍性：** 這代表「封閉且具備高度內部術語的知識庫」都可以被 Agent 化。
   * **洞察：** 任何具備「專有法典 / 規則書」的長尾領域（如：地方建築法規、特定宗教法、IC 代工廠的 Design Rule），都有打造專屬檢索與審查 Agent 的空間。

## 三、短期看法（一個月內）

1. **EDA 流程的「外掛式」整合：** 既然 hardware-eda 落地的最大阻礙是封閉工具，你可以在自己建構的 pipeline 中，利用 Python 或 Bash 腳本將 EDA 工具的 Log 導出，讓 Claude Code 擔任純粹的 Verify / Analyze 角色，避開讓 AI 直接操作 EDA 工具的雷區。
2. **切入「髒資料清理」：** 參考 sales-crm 與 data-analytics 缺少的 Verify 能力，用 ccr 寫一個能對接 CSV 或特定資料庫，專做「異常值標記與格式修正」的厚重工作外包腳本，這能立刻省下大量人工 review 時間。

## 四、中期看法（一季內）

1. **「配置（Configure）」將成為下一個熱門 AI 任務：** 當生成內容不再稀缺，如何讓 AI 產出的東西符合企業既有的環境（設計規範、程式碼風格、法務用詞）將是重點。推論：我賭接下來半年，主打 "Style-aligned" 或 "Policy-compliant" 的 Agent 框架會崛起。
   * **證明我錯的訊號：** 如果大型模型（如 GPT-5 或 Claude-4）原生的 Context Window 內建了極強的 Few-shot 對齊能力，導致「外部配置」變成多此一舉。
2. **Orchestrate（調度）權限會持續被限縮在純軟體圈：** 除了 devops 與 ai-agent-tooling 敢讓 AI 自動執行腳本，其他領域仍會死守審核權。推論：不要在傳統產業（醫療、法務、硬體）推銷全自動 Agent，要推銷「具備精美審核介面的 Copilot」。
   * **證明我錯的訊號：** legal-compliance 或 healthcare-bio 的 Orchestrate 任務在下一季的數據中突破預期值的 30%。

## 五、對讀者的具體意涵

1. **IC Design Pipeline 優化：** 你的日常工作（baseband IC）存在大量硬體規格書（Datasheet）與韌體暫存器（Register）的對接。這就是一種「法典審查（教會法律師的痛點）」。可以建置一個專抓 Datasheet 更新並自動對比當前 Verilog/C Code 實作是否有落差的 Verify Pipeline。
2. **Substack 選題 HOOK 建議：**
   * **「為什麼你的銷售團隊不該用 AI？」**（切入點：CRM 資料越搞越髒的災難，帶出 Verify 的重要性）
   * **「工程師的特權：只有我們敢讓 AI 自己扣板機」**（切入點：全領域數據解析，解析 Orchestrate 任務的產業斷層）
   * **「別做生成了，企業願意為『配置』付錢」**（切入點：B1 缺口數據，論證 Configure 任務的商業潛力）

## 訊號可信度

* **極度堅實：** 各領域的「上線率（Production Pct）」差距。這是兩萬多筆資料堆出來的結構，清楚反映了產業特性（容錯率高低）。
* **容易被低估：** 法務、醫療、金融、硬體 / IC 設計。**（重要前提）** 由於樣本來自 GitHub 公開語料，這些高度注重機密、原始碼不外流的產業，其實際的 AI 應用程度絕對比數據顯示的更深。他們可能在內網架設了極為複雜的 workflow，只是你在此表中看不到。
* **樣本單薄需警惕：** `sales-crm` (n=130) 與 `education-training` (n=163) 的任務分佈（B1）數字容易因少數專案而產生劇烈跳動，不宜作為砸重金開發產品的單一證據，僅適合做為探索方向。
* **星數（Stars）無效：** 表中的 star 數為 repo 層級，只能證明「這個 skill 掛在一個有名的 repo 裡面」，完全無法代表該 skill 實際的受歡迎程度或有效性，本報告已刻意排除以此作為論證依據。
