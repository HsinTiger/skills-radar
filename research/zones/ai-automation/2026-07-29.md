## Strategic Intelligence Brief

### 模型與單點工具正在商品化，價值正上移到可治理的 Agent Harness

下一波差異化不在再做一個會回答問題的代理，而在把資訊入口、脈絡壓縮、持久狀態、工具路由、評測觀測、隔離執行與證據契約組成可恢復的控制平面。

**待爆發賽道：Evidence-Governed Domain Agent Harness**

聚焦高風險工程與 ASIC automation：把設計意圖、驗證意圖、確定性執行包、真實工具證據與 owner approval 串成一條可稽核鏈，而不是投入通用爬蟲或提示工程。

反方觀點：熱門專案的星數、文件自述節省量與平台覆蓋不等於企業採用或可靠性；原生模型能力也可能快速吸收部分框架價值。

### 催化劑

- 工具數量增加後，動態發現與最小權限路由比把所有工具塞進上下文更重要
- 長任務與多代理協作需要 conversation 外的 checkpoint、重試、取消與 readback
- 企業開始要求 trace、evaluation、sandbox、資料邊界與人類核准能同時成立
- 模型價格與能力收斂，使 domain evidence contract 成為更持久的差異化資產

### 領先指標

- 開源專案是否從 agent demo 轉向 checkpoint、conformance、doctor 與 rollback
- 工具整合是否改採 runtime discovery、scoped auth 與可撤銷 session
- evaluation 是否能連回確切輸入、工具呼叫、輸出與失敗分類
- sandbox 是否提供網路、檔案、credential 與 artifact 的明確政策及 readback
- 同一 evidence contract 是否能跨至少三個 domain task 重現

  - Canary：公開 toy datapath 的 intent→RTL/SVA→simulation evidence bundle 與獨立 claim audit。
  - Promotion gate：另一個 worker 可只靠 bundle 重現，且 false-PASS negative test 能被 gate 擋下。
- **EDA Tool Capability Registry**：把 VCS、Verdi、lint、CDC、synthesis、LEC/ECO 的 capability、preflight、版本與失敗原因型別化。
  - Canary：先用 mock adapter 驗證 allowlist、negative authorization、artifact manifest 與 fallback，不連公司工具。
  - Promotion gate：進核准環境後，真實 tool/version/command/report readback 能對上相同 schema。
- **Frontend ECO Failure Replay**：前端 ECO 的稀缺價值不是自動改 RTL，而是保存 root cause、變更邊界、等價性預期與 rollback 證據。
  - Canary：公開 combinational/sequential toy change 的 before/after cone、test、equivalence expectation 與 rollback trace。
  - Promotion gate：無 owner approval 不改 source；沒有 LEC/正式等價性 readback 不宣稱 ECO 正確。

## IC Design Automation Build-up Blueprint

> `PROPOSED_REQUIRES_OWNER_APPROVAL` · OA_CONTEXT=PARTIAL · NX_CONTEXT=SNAPSHOT_ONLY

把每次 IC 設計變更壓成可恢復的 intent→execution→evidence→decision loop；工程師只需要看變更邊界、最早可信失敗與真正需要裁定的問題。

### 六層 build architecture

#### 1. 可重現環境底座

任何核准 worker 都能從乾淨 checkout，以單一入口重現同一個 stage。

- Build：repo-owned control plane；流程狀態不只存在 agent 對話
- Build：tool capability registry：版本、license/preflight、輸入輸出、side effect、timeout 與 fallback
- Build：content-addressed artifact store、固定 seed、相對路徑、原子寫入、idempotent rerun
- 核心產物：tool_capabilities.json、run_manifest.json、environment_readback.json
- Promotion proof：clean-checkout replay、版本/readback 相符、缺工具或權限時 fail closed
- 降低認知負載：工程師不再反覆追問『跑的是哪一版、哪個工具、哪個目錄』。

#### 2. 加速迭代與失敗重播

每次變更先跑最便宜且足以推翻 claim 的 gate，再逐級升級。

- Build：diff impact map：變更 requirement/module/interface/assertion 對應受影響測試與 EDA stage
- Build：fast/medium/signoff 三速 queue、checkpoint/resume、cache validity 與 duplicate-run suppression
- Build：保存 first failing seed、最早 divergence、輸入版本、工具版本與最小 replay command
- 核心產物：impact_map.json、gate_plan.json、failure_replay.json
- Promotion proof：另一個 worker 可重現同一最早失敗；cache miss/hit 理由可讀回
- 降低認知負載：把『重跑整包再看海量 log』改成『先看最小失敗與受影響 cone』。

#### 3. 準確度與 false-PASS 防線

準確度先定義成 claim 可追溯、oracle 可重現、弱 gate 不冒充強 gate。

- Build：design intent／verification intent schema：width、signedness、fixed-point、cycle、reset、protocol、non-goal
- Build：requirement→assertion/test/coverage/evidence traceability；每個 UNKNOWN 保留 owner/next check
- Build：negative fixture、mutation、vacuity、X/unknown、boundary 與 stale-golden 檢查
- 核心產物：design_intent.yaml、verification_intent.yaml、claim_ledger.jsonl
- Promotion proof：故意植入的 false PASS 能被擋下；每個 PASS 可回到 oracle、輸入、版本與 exact gate
- 降低認知負載：工程師不用重讀整份報告，只審未證實假設、衝突與 promotion decision。

#### 4. 認知負載與 owner decision surface

每次只呈現三件事：改了什麼、最早可信失敗在哪、哪個問題必須由 owner 決定。

- Build：resumable checkpoint：intent、assumption、evidence、failure、decision、exact next action
- Build：相同結果自動折疊；新風險、authority conflict、irreversible action 才打斷 owner
- Build：把零散問題批次化成 recommendation／alternatives／consequences／default decision packet
- 核心產物：checkpoint.json、decision_packet.md、owner_disposition.json
- Promotion proof：handoff 不需重講背景；可量測 interruption、重複提問、恢復工時與 owner correction
- 降低認知負載：AI 承接記憶與可逆執行，人保留高價值架構判斷與不可逆裁定。

#### 5. EDA 方法論與 typed evidence adapter

每個 EDA stage 只回答自己有權回答的問題，輸出 typed evidence 而非自然語言 PASS。

- Build：adapter 共通 contract：tool/version/command/input hash/corner/seed/status/report hash/line/quote
- Build：lint、compile/elaboration、simulation、CDC/RDC、formal、synthesis、LEC 分開建 authority 與失敗型別
- Build：先做 mock/conformance adapter；進 NX 後再用核准報告校準 parser 與 negative fixture
- 核心產物：eda_capabilities.json、evidence_manifest.json、gate_result.json
- Promotion proof：unknown format、空報告、零 compared points、缺 corner/version 或 parser ambiguity 一律不升級 claim
- 降低認知負載：把不同工具 log 統一成可排序 failure taxonomy，但保留原始 report provenance。

#### 6. Verification factory

把單點 testbench 經驗轉成可跨 block 重用的 oracle、observer、assertion、coverage 與 replay pattern。

- Build：Reference Model 是 expected 唯一來源；Scoreboard 只負責配對與 bit-true compare
- Build：cycle/reset/valid-ready/backpressure contract 加上多節點 observer，找 earliest divergence
- Build：directed boundary、constrained-random、assertion/formal、coverage hole、ECO equivalence 各自有 exit gate
- 核心產物：verification_plan.yaml、traceability_matrix.json、coverage_ledger.json
- Promotion proof：正常、邊界、故障注入與 stale/misaligned oracle 都能得到預期 verdict；重跑結果一致
- 降低認知負載：debug 從『最後輸出錯了』縮成『哪個 contract、哪個節點、哪個 cycle 首次偏離』。

### 分層 verification ladder

- **G0 · Intake/Preflight**（每次 task／環境變更）：intent/schema、source pin、tool capability、permission、golden/version readback
  - 邊界：輸入不完整、authority 衝突、tool/version 不符就停止。
- **G1 · Fast structural**（每次 RTL／TB candidate diff）：format/parser、compile/elaboration、lint、width/signedness/X/reset 靜態檢查
  - 邊界：只證明結構 gate；不得寫成功能 PASS。
- **G2 · Block behavior**（G1 通過後）：directed smoke、bit-true oracle、cycle assertions、boundary/mutation negative tests
  - 邊界：先保留 first failure；不要用後續大量錯誤淹沒 root cause。
- **G3 · Regression/debug**（checkpoint／合併前）：impact-selected regression、fixed seeds、multi-node earliest divergence、coverage holes
  - 邊界：coverage 數字缺 denominator 或 waiver 無 owner disposition，不能 closure。
- **G4 · Structural proof**（跨 clock/reset、控制協定或高風險變更）：CDC/RDC、SVA/formal、assumption/vacuity、counterexample replay
  - 邊界：inconclusive、vacuous、unreachable 與 proven 必須分開。
- **G5 · Synthesis/ECO promotion**（RTL frozen／frontend ECO）：synthesis report、constraint/corner readback、LEC substance、rollback bundle
  - 邊界：沒有 compared points、unproven points=0 與真實 report readback，不宣稱 equivalence。
- **G6 · Owner disposition**（任何 sign-off 或 source mutation 前）：Claim／Evidence／Risk、waiver、residual risk、owner accept/reject/defer/verify
  - 邊界：AI narrative、unit test 或 parser PASS 永不自動升格 sign-off。

### 最重要的 verification patterns

- **P0 · Contract-to-check traceability**：每個 requirement 綁定 assertion/test/coverage/oracle/evidence；未綁定即 UNKNOWN。
  - 主要防止：漏驗需求、文件與 RTL 認知漂移、沒有證據的 satisfied claim。
- **P0 · Reference Model／Scoreboard 分責**：Reference Model 唯一產生 expected；Scoreboard 只做 transaction pairing 與 bit-true compare。
  - 主要防止：oracle 與 checker 同錯、scoreboard 隱藏計算、debug 無法判斷誰錯。
- **P0 · Cycle／Reset／Protocol contract**：明列 latency、valid-ready、bubble/backpressure、reset window、flush 與例外；用 assertion 執行化。
  - 主要防止：off-by-one、reset race、gap 才出現的錯位、吞吐與資料配對錯誤。
- **P0 · Multi-observer earliest divergence**：在高資訊量中間節點保存 act/exp 與 cycle metadata，先找第一個可信偏離。
  - 主要防止：只看到最終 mismatch、波形 probe 無界擴張、跨 pipeline 猜 root cause。
- **P0 · False-PASS mutation test**：故意破壞 width、signedness、latency、reset、golden freshness 或 compared-points，確認 gate 會失敗。
  - 主要防止：checker 沒接上、vacuous property、空報告 PASS、stale golden 與弱 gate 冒充強 gate。
- **P1 · Atomic transaction-field alignment**：transaction、driver、monitor、sequence、reference input schema 視為同一原子變更並做欄位 diff。
  - 主要防止：欄位漏抄造成 X-taint、driver/monitor semantic drift、可跑但答案錯。
- **P1 · Golden provenance and differential oracle**：golden 綁 source/version/parameter/seed/hash；必要時以兩個獨立 oracle 做 differential check。
  - 主要防止：不同批次 golden 混用、reference 版本漂移、模型與 RTL 同源錯誤。
- **P1 · Formal assumption／vacuity audit**：assert/assume/cover 分離，保存 PROVEN/CEX/VACUOUS/INCONCLUSIVE/UNREACHABLE。
  - 主要防止：過度 constraint、property 根本未觸發、bounded proof 被誤稱完整。
- **P1 · Coverage with denominator and holes**：coverage 必帶 scope、denominator、unreachable/waiver、對應 requirement 與未覆蓋樣本。
  - 主要防止：漂亮百分比掩蓋沒採到的功能、coverage closure 無需求語意。
- **P0 · ECO equivalence plus rollback**：保存 before/after cone、intent、LEC compared/unproven points、simulation delta 與可回退版本。
  - 主要防止：heuristic diff 被誤稱等價、ECO 修 A 壞 B、無法重播或回退。

### 90 天 MVP

- **0–30 天 · Control plane**：intent schema、capability registry、run/evidence manifest、mock adapters、owner decision packet
  - Exit：公開 toy task 可 clean-checkout 重跑；缺工具/權限/證據會 fail closed。
- **31–60 天 · Verification kernel**：toy fixed-point datapath、Reference Model/Scoreboard、cycle/reset assertions、multi-observer、五種 mutation
  - Exit：每種故障都得到預期 verdict，另一個 worker 可重現 earliest divergence。
- **61–90 天 · NX adapter canary**：經 owner 核准後，只接一條真實 compile/sim/report readback；再評估 CDC/formal/synthesis/LEC
  - Exit：tool/version/command/input/report hash 可對帳；沒有真 EDA evidence 就停在 experiment。

### Owner decision

- 建議：第一個 MVP 選 RTL／DV Evidence Kernel，先完成公開 toy datapath 的五種 false-PASS mutation 與 replay bundle。
- 替代：若先做 tool registry，環境治理更快，但短期無法證明 verification value。
- 若暫緩：維持公開 blueprint 與 mock adapter，不進 NX、不改任何產品 RTL。
- `requires_owner_approval=True`

## Automation／研究路線

### 1. Evidence kernel 與 change governance

先定義 task、intent、approval、failure、artifact 與 claim boundary，再選 framework。

候選：Agentic Harness Engineering

證據：change manifest、failure taxonomy、owner disposition 與 rollback readback

### 2. Public intake 與 typed tool registry

公開來源 adapter 具備 capability probe、ordered fallback、allowlist 與 provenance。

候選：Agent-Reach、MCP Reference Servers

證據：active backend、scope、negative authorization 與 source provenance

### 3. Durable state 與 reversible context

讓長任務能中斷續跑，並讓壓縮後的原始證據可按需取回。

候選：LangGraph、Headroom

證據：checkpoint conformance、idempotence、uncompressed holdout 與 retrieval trace

### 4. Evaluation rail 與最小權限執行

trace 連回 oracle，sandbox 明確限制網路、檔案、credential 與 artifact。

候選：Langfuse、E2B

證據：sanitized trace、eval linkage、policy readback 與 isolation negative test

### 5. ASIC automation domain adapter

把設計意圖與驗證意圖編譯成確定性 bundle，工網只跑既有 EDA flow 並回傳證據。

候選：尚無

證據：公開 toy RTL 先過 canary；內部 claim 只接受核准環境的真實工具證據
