## 🌊 社群風向（訊號，非事實）

1. **長 Context 工具調用中，Agent Skills 發生「白盒衰退」（arXiv: 2607.17937 / 2607.17598）**
   - *研判*：論文實證指出，即便將 Skill 載入系統，隨著 Agent 執行工具與對話 Context 拉長，模型對 Skill 中提示規範與檢核點的遵從率會劇烈下降。這給出了明確訊號：**不要把「巨型規範」一次性塞給 Agent**。「 Progressive Disclosure（漸進式揭露）」與按需調用的動態路由才是維持長任務精準度的唯一架構。
2. **多 Agent 系統的「通道污染」與特權不對等風險（arXiv: 2607.19430 / 2607.19595）**
   - *研判*：`ChannelGuard` 與 `Twin Agent` 論文揭露重大防禦死角：單一模型安全不等於系統安全。當 Planner、Worker 與 Verifier 串聯時，未經隔離的中繼通道會成為 Prompt Injection 的絕佳破口（例如 Worker 爬取外部網頁後，將隱藏指令傳給高權限 Planner）。自建市場監控與社群發文 Pipeline 必須在 Agent 間實施「特權分離」，未經淨化的外部資料絕不能直接餵入執行 Shell 或系統寫入的 Agent。
3. **Claude Code 30 天本機對話紀錄自動刪除與檔案誤刪疑慮（HN 熱議）**
   - *研判*：社群爆出 Claude Code 會自動清理 30 天前的本機 Context 歷史，且存在 Agent 執行重構時誤刪使用者檔案的案例。對重度依賴本機 CLI（Claude Code / agy / ccr）處理厚重工作的使用者來說，**絕不能把本機歷史當作知識庫備份**。所有產出的知識（如曼報、IC/WiFi 知識庫）必須強制自動 Commit 並推送到獨立存儲庫，且 CLI 執行權限必須受限於獨立 git branch。
4. **Claude Code 系統提示詞（System Prompt）大幅精簡 80%（HN 熱議）**
   - *研判*：Anthropic 官方大幅砍掉 Prompt 贅字以提升回應速度與控制力，同時被社群發現硬編碼限制 Opus 5 使用 Subagent。這代表官方 Harness 正從「提示詞說服」轉向「硬性沙盒與 Harness 管控」。使用者在寫自己的系統規格時，也應砍掉中庸廢話，用硬性腳本限制 Agent 的邊界。

## 🎯 策略建議

### 短期（一週內）
1. **防禦檔案遺失與歷史清理**：檢查本機 `claude-code` 與 `agy` 執行的工作目錄。為所有自動化 Pipeline（Substack 發文、知識庫更新）建立獨立 git 工作區，並在 Cronjob 中加入「執行完畢自動 git status 比對與自動 Push」機制，防止 30 天本機 Context 遭刪除或檔名誤刪造成不可逆損失。
2. **精簡巨型 Skill 檔**：盤點目前使用的自訂 Skill，若有單一檔案超過 300 行的「大百科型 Skill」，立即拆解。改為僅保留摘要導引，詳細規格改由 Agent 根據子任務動態讀取，以解決長 Context 下的指令衰退問題。

### 中期（一個月內）
1. **建構多 Agent 跨通道過濾器（Channel Guard Filter）**：在市場監控與社群自動化 Pipeline 的「爬蟲/外部資料輸入」與「發文/決策 Agent」之間，硬性插入一層清道夫腳本（Sanitizer），過濾所有 HTML/Markdown 中的可疑提示詞指令，實現特權分離。
2. **自動化資料擷取 Pipeline 防爆升級**：修正情報抓取腳本，針對 `gh` CLI 及外部 API 補齊健康檢查（Healthcheck）與例外處理，防止擷取失敗時產生空數據污染知識庫。

### 長期（一季內）
1. **全面轉向「Progressive Disclosure + 靜態 Harness」架構**：放棄依靠「龐大 Prompt」來規範 Agent 的幻想。將架構明確劃分為：**你負責規格與稽核（Spec & Audit）** ➔ **輕量化 Router 決定載入何種 Skill** ➔ **沙盒化 CLI 外包執行**。只防守「檔案毀損」與「憑證外洩」的出局風險，其餘徹底放手讓自動化 Agent 跑。
