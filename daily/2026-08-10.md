## 🔴 官方變動（事實）
- **`anthropics/claude-code` 發布 v2.1.224 - 226**：
  - **新增 Self-hosted Runner (Team/Enterprise)**：允許將自己的機器或容器變成 Claude Code 的執行環境。這代表官方正式打通了內網/地端部署的最後一哩路，這對依賴高機密資料庫或本機硬體（如 EDA tools）的開發者是重大突破。
  - **新增 Archive Plugin Source**：支援透過 HTTPS 直接安裝 zip 外掛，並附帶 SHA-256 驗證，不再強依賴 git 或 npm。這降低了隔離環境（Air-gapped）或嚴格 CI/CD 流程中的部署門檻。
  - **安全與權限控制強化**：新增 Gateway 支出上限提示、未信任目錄的安全提示（workspace trust prompt），並修正 Auto Mode 在被安全攔截時的配額計算。
- **`anthropics/claude-plugins-official` 依賴升級**：
  - 更新 `hyperframes`, `deepeval`, `nimble`, `qodo`, `wix`, `lumen`, `remember` 等外掛版號，官方外掛生態系維持常規維護與穩定化，無破壞性變動。

## 🌊 社群風向（訊號，非事實）
1. **全自動模式（Auto Mode）成為開發者預設期待**：HN 討論中「Auto mode is now the default」與「Codex Desktop Won」的熱度，顯示開發者對於被打斷、需頻繁授權的半自動模式已失去耐心。市場正在向「設定好防護網後放手讓 Agent 跑到底」的體驗靠攏。
2. **多通道路由（Routing）需求爆發**：`Panniantong/Agent-Reach` 星數單日暴增 887，並在最新版將自身定位為「能力層多後端路由」。這反映了在做自動化發文或爬蟲 pipeline 時，單一渠道極易因風控失效，開發者需要 Agent 自己具備 fallback 與重試的機制。
3. **垂直領域與工程閘門（Gate）Skill 湧現**：GitHub 出現 `neuroarxiv`（設計前先查文獻）、`ironcode`（生產環境程式碼品質閘門）以及針對特定硬體與場景（如 NVSHMEM、iOS App Store 送審）的專屬 Skill。開發者不再需要「幫我寫程式」的通用技能，而是需要「按我團隊標準稽核」的 SOP 封裝。

## 🛡️ 安全情報
- **預設風險底線**：Snyk ToxicSkills 2026-02 掃描 3,984 個 skill，36.82% 含安全缺陷、13.4% critical、76 個確認惡意負載。安裝任何第三方 skill 的預設風險底線不變。
- **新知風險：軌跡污染攻擊 (Trajectory Poisoning)**：arXiv 論文指出（2608.05563v1），能夠自我進化的 Agent 若擷取了有毒的歷史執行軌跡，會將惡意經驗內化為「可信的 Skill 指令」。這意味著自動化萃取 workflow 為 skill 的過程必須有人工稽核。
- **新知風險：隱藏功能重建 (Behavioral Skill Reconstruction)**：論文（2608.04192v1）證實，即使封裝或閉源 Skill 檔案，攻擊者仍可透過互動重建隱藏的 prompt 或邏輯。絕對不要在 Skill 檔案中 hardcode 內網密碼、API Keys 或機密業務邏輯。

## 🎯 策略建議

### 短期（一週內）
1. **在內網機器部署 Self-hosted Runner**：既然 Claude Code 支援了，立刻在你的 baseband IC 開發伺服器（含有 EDA tools 授權與 RTL code 的環境）上拉起 Runner。這能省去以往要在外網寫好 script 再搬進去跑的摩擦力，讓 Agent 直接對著真實環境下指令。
2. **停用未經隔離的危險本機 Skill**：鑑於 Auto mode 預設開啟且學界頻繁警告檔案系統層級的攻擊，全面盤點你目前 `~/.gemini/config/skills` 裡的第三方工具。若是會執行 `rm`、`curl` 或修改系統設定的技能檔，在沒有套用沙盒前，應一律移除或降級為純建議模式。

### 中期（一個月內）
1. **建立內網私有 Zip Plugin 派發中心**：利用 Claude Code 新增的 `archive` plugin 來源功能，把你手邊的「曼報知識庫爬蟲」、「Substack 發文 SOP」打包成 zip 並計算 SHA-256，放在內網。讓所有 CI runner 或本地 CLI 工具統一且安全地拉取你的專屬 SOP，取代目前各自為政的 prompt。
2. **將 Agent-Reach 概念引入你的自動化 Pipeline**：如果你有社群發文的管線，參考 Agent-Reach 的「首選+備選路由」機制。不要讓 Agent 死磕單一 API，而是把「失敗後切換通道」的邏輯寫進自建的 Skill 中。

### 長期（一季內）
1. **建構「零信任」的 Agent 執行環境（Zero-Trust Agent Environment）**：隨著 Agent 自動化程度加深（不用你按 Y），出局風險在於 Agent 誤刪資料庫或洩漏智財。你必須將基礎設施轉向防禦性架構：引進如 E2B Sandbox 的機制，讓 Agent 只能在拋棄式的沙盒內編譯與測試，通過你的自動化測試腳本（如 ironcode 的概念）後，才由 CI/CD pipeline 進行 merge 與部署。不要給予 Agent 任何直接操作 production 環境的 credential。
