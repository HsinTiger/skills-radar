## 🛡️ 安全情報
今日 arXiv 湧現大量針對 Agentic 系統的攻擊研究，顯示攻擊手法正在快速進化：
1. **登入邊界成為突破口 (LoginTrap)**：網頁 Agent 在處理登入等敏感認證邊界時，極易受到釣魚式間接提示詞注入（IPI）攻擊。
2. **搜尋 Agent 的目標劫持 (Breadcrumbing)**：依賴外部搜尋結果的 Agent 面臨嚴重的內容注入風險，攻擊者可透過動態網頁內容誘導 Agent 偏離原定任務。
3. **動態環境觸發的惡意技能 (SkillSentry)**：部分 Skill 在靜態分析下看似無害，但會在特定環境狀態或歷史互動後觸發惡意行為。

## 🎯 策略建議

### 短期（一週內）
1. **盤點認證邊界**：檢視你現有 pipeline 中 agy 或 ccr 是否擁有自動存取密碼管理員或執行敏感登入的權限。若有，立即加入 Human-in-the-loop 阻斷點，避免遭到網頁內容的 IPI 攻擊（參考 LoginTrap 研究）。
2. **評估 Uber ADR 監控機制**：前往 `uber/ADR` repo 檢閱其開源架構。**不要直接安裝**，先閱讀程式碼了解大廠如何攔截與稽核 Agent 的底層系統呼叫，評估是否能整合進你本機的 CLI 流程中作為第二道防線。

### 中期（一個月內）
- **沙盒化自建與第三方 Skill**：學界已證實靜態分析無法完全防堵動態觸發的惡意行為。針對你從社群引入的自動化腳本或 Skill，應建立基於 OS 層級或容器化的沙盒環境進行動態行為測試（Honey Worlds），嚴格限制其存取範圍，不要給予 global 權限。

### 長期（一季內）
- **全面轉向零信任 Agent 架構**：隨著 Agent 依賴外部搜尋與 API 回傳值的程度加深，間接提示詞注入（IPI）將成為常態威脅。你的自動化體系必須從「假設 Agent 不會做壞事」轉向「隔離 Agent 的執行破壞力」。將「資料蒐集 Agent」與「操作執行 Agent」物理切割，嚴禁負責上網解析未驗證內容的 Agent 擁有寫入核心知識庫或執行 Shell 的權限。
