owner-personalized research zone · 2026-08-08

EDA／數位 IC 設計專區

對 WiFi baseband ASIC，先自動化意圖與證據，再自動化 RTL mutation。最有價值的不是把第三方 skill 整包裝進公司環境，而是抽出可審查契約，由 OA 產 deterministic bundle、NX 跑真實 EDA、證據回流後才升級 claim。

規格、fixed-point、microarchitecture、RTL、lint/CDC/RDC、formal/SVA、VCS/Verdi、UVM、logic synthesis、LEC 與前端 ECO。

排除：FPGA/Vivado/Quartus/bitstream、MCU/firmware/embedded、board/PCB、analog/RF/antenna，以及 P&R/CTS/route/physical signoff。

為你設計的下一步路線

  1. 1. 設計意圖編譯器

    design intent、cycle contract、fixed-point/interface/reset invariants 與 acceptance boundary。

    候選：review-rtl-architecture、rtl-p3-uarch-policy、rtl-quality-reviewer、spec-planner、systemverilog-rtl-generator、digital-front-end-skill、rtl-specification-consistency-checker
    證據：spec/cycle table readback；尚不是 RTL 功能 PASS。

  2. 2. Verification contract factory

    stimulus space、bounded wait、scoreboard、reset/backpressure、coverage exit gate。

    候選：尚無通過篩選的候選
    證據：VCS compile/sim、seed manifest、mismatch log 與 coverage readback。

  3. 3. Spec-linked property factory

    每條 candidate property 對應 requirement，分開 assume/assert/cover。

    候選：formal-verification、rtl-property-inference、rtl-p5s-sva-check、assertion-design
    證據：正式 proof result、vacuity 與 counterexample review。

  4. 4. VCS／Verdi 證據萃取器

    可重跑的 FSDB event/coverage query 與 bounded JSON evidence。

    候選：systemverilog-waveform-debug、x-npi、write-sim-testbench
    證據：同一 clock edge sampling、API readback、compile/sim status 與 denominator。

  5. 5. Synthesis／LEC／ECO claim governor

    RTL/filelist/tool/library/constraint manifest；lint、DC、LEC 與前端 ECO claims 分層。

    候選：assess-synthesis-and-inference、hw-cdc、equivalence-check、prepare-rtl-for-synth、logic-synthesis、rtl-repair
    證據：真實 DC／Formality/LEC／ECO report readback；各 gate 不互相替代。

  6. 6. Evidence-backed learning loop

    只回流獲准的 manifest、claim、失敗模式與通用方法，形成跨 block 可複用資產。

    候選：尚無通過篩選的候選
    證據：另一個 agent 可由 checkpoint 重現 exact next action，不需 owner 重講上下文。

前九十天

  • 三十一到六十天：接 VCS compile/elaborate/sim 與只讀 Verdi/FSDB evidence。
  • 六十一到九十天：接 DC、Formality/LEC 與前端 ECO evidence；自動改 RTL 保留在最後。

ArabelaTso/Skills-4-SE · commit 3ec09ea2bbf8b8626aea4e1bdd769de66b0adc35 · Apache-2.0

在你的系統中的角色：spec-linked-property-candidate

適合把 cycle contract 與不變量轉成候選 SVA，但必須保留 spec requirement、assume/assert/cover 與 vacuity 邊界。

第一個 canary：對公開 FIFO 或 ready/valid toy block 產生少量候選 property；owner 逐條連回 requirement，再由正式工具 proof。

採用證據、風險與淘汰條件

需要的證據

  • requirement-to-property mapping
  • assumption ledger
  • proof engine/result
  • vacuity 與 counterexample review

已知風險

  • inferring intent from RTL can reproduce existing bugs
  • liveness/fairness assumptions need owner confirmation
  • no actual proof execution

立即淘汰

  • 要求自動修改產品 RTL 或繞過 owner approval
  • 把 parser/lint/open-source PASS 宣稱成產品功能、PPA 或 signoff PASS
  • 無法 pin source/license，或需要外傳內部訊號、license、PDK、SDC 與報告內容

owner 核准後，先通過公開 toy design canary，再以核准的 deterministic bundle 進 NX；只有真實 VCS／Verdi／DC／Formality/LEC 或 ECO evidence 能提升對應 claim。
