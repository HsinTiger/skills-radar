Evidence-Governed Domain Agent Harness

聚焦高風險工程與 ASIC automation：把設計意圖、驗證意圖、確定性執行包、真實工具證據與 owner approval 串成一條可稽核鏈，而不是投入通用爬蟲或提示工程。

反方觀點

熱門專案的星數、文件自述節省量與平台覆蓋不等於企業採用或可靠性；原生模型能力也可能快速吸收部分框架價值。

催化劑

  • 工具數量增加後，動態發現與最小權限路由比把所有工具塞進上下文更重要
  • 長任務與多代理協作需要 conversation 外的 checkpoint、重試、取消與 readback
  • 企業開始要求 trace、evaluation、sandbox、資料邊界與人類核准能同時成立
  • 模型價格與能力收斂，使 domain evidence contract 成為更持久的差異化資產

領先指標

  • 開源專案是否從 agent demo 轉向 checkpoint、conformance、doctor 與 rollback
  • 工具整合是否改採 runtime discovery、scoped auth 與可撤銷 session
  • evaluation 是否能連回確切輸入、工具呼叫、輸出與失敗分類
  • sandbox 是否提供網路、檔案、credential 與 artifact 的明確政策及 readback
  • 同一 evidence contract 是否能跨至少三個 domain task 重現
什麼會推翻這個 thesis
  • 原生模型平台在不犧牲可攜性下完整吸收 durable state、evaluation 與 policy control
  • 增加 harness 層後沒有降低失敗重現時間或 owner 介入次數
  • context compression 在真實任務上造成關鍵約束遺失且無法由可逆取回機制補救
  • domain workflow 無法產生可機器讀取的工具證據，只剩敘事型報告

輸入與 claim boundary

跨任務 reproducibility、owner interruption、recovery effort、evidence integrity、外部需求訊號

內部效率或 demo 不等於付費需求；EDA claim 仍需核准環境真工具證據。

利基篩選器

  • 高頻或高代價工程痛點，但公開 skill 供給稀疏
  • 模型能力提升後仍需要的 domain schema、oracle、evidence 與 approval
  • 可先用公開 fixture 驗證，之後以 deterministic bundle 進核准環境
  • 能降低失敗重現時間、重複脈絡說明或 owner interruption，且不犧牲 verification integrity

對你工作最有價值的三個假設

  1. RTL／DV Evidence Kernel

    把 requirement、cycle contract、assertion、simulation artifact、review claim 與 owner disposition 串成同一 ledger。

    Canary：公開 toy datapath 的 intent→RTL/SVA→simulation evidence bundle 與獨立 claim audit。
    升級 gate：另一個 worker 可只靠 bundle 重現，且 false-PASS negative test 能被 gate 擋下。

  2. EDA Tool Capability Registry

    把 VCS、Verdi、lint、CDC、synthesis、LEC/ECO 的 capability、preflight、版本與失敗原因型別化。

    Canary：先用 mock adapter 驗證 allowlist、negative authorization、artifact manifest 與 fallback，不連公司工具。
    升級 gate：進核准環境後，真實 tool/version/command/report readback 能對上相同 schema。

  3. Frontend ECO Failure Replay

    前端 ECO 的稀缺價值不是自動改 RTL，而是保存 root cause、變更邊界、等價性預期與 rollback 證據。

    Canary：公開 combinational/sequential toy change 的 before/after cone、test、equivalence expectation 與 rollback trace。
    升級 gate：無 owner approval 不改 source；沒有 LEC/正式等價性 readback 不宣稱 ECO 正確。

分析工具的 authority 邊界

Production：deterministic Python builders、versioned JSON evidence、tests 與 Pages readback

Exploration：Jupyter notebook 僅用於 cohort、trend、niche hypothesis 與圖表探索；結論須回寫受測試的 pipeline

AI：AI 撰寫 thesis／anti-thesis 與決策敘事，但不能覆寫 evidence ledger 或工具結果

為你設計的下一步路線

  1. 1. Evidence kernel 與 change governance

    先定義 task、intent、approval、failure、artifact 與 claim boundary，再選 framework。

    候選：Agentic Harness Engineering
    證據：change manifest、failure taxonomy、owner disposition 與 rollback readback

  2. 2. Public intake 與 typed tool registry

    公開來源 adapter 具備 capability probe、ordered fallback、allowlist 與 provenance。

    候選：Agent-Reach、MCP Reference Servers
    證據：active backend、scope、negative authorization 與 source provenance

  3. 3. Durable state 與 reversible context

    讓長任務能中斷續跑，並讓壓縮後的原始證據可按需取回。

    候選：LangGraph、Headroom
    證據：checkpoint conformance、idempotence、uncompressed holdout 與 retrieval trace

  4. 4. Evaluation rail 與最小權限執行

    trace 連回 oracle，sandbox 明確限制網路、檔案、credential 與 artifact。

    候選：Langfuse、E2B
    證據：sanitized trace、eval linkage、policy readback 與 isolation negative test

  5. 5. ASIC automation domain adapter

    把設計意圖與驗證意圖編譯成確定性 bundle，工網只跑既有 EDA flow 並回傳證據。

    候選：尚無通過篩選的候選
    證據：公開 toy RTL 先過 canary；內部 claim 只接受核准環境的真實工具證據

前九十天

  • 前一個月：完成 evidence kernel、tool registry、checkpoint 與負向權限測試。
  • 第二個月：在公開 toy RTL 串起 intent→candidate artifact→sim/formal evidence 的可恢復流程。
  • 第三個月：用核准的 deterministic bundle 接現有工具；量測失敗重現時間、owner 介入與證據完整性。

Agentic Harness Engineering

china-qijizhifeng/agentic-harness-engineering · commit faf44bc4aea57413c520bc5711c6ebf628e0da1e · MIT

在你的系統中的角色：harness-change-governor

最貼近你要搭建的 ASIC automation：每次改 system rule、tool、memory 或 middleware 都有失敗證據、預期修復與回歸清單。

第一個 canary：以公開 toy RTL 任務建立最小 change manifest，讓另一個 agent 重跑前後版本並核對預測修復與回歸。

採用證據、風險與淘汰條件

需要的證據

  • failure trace
  • change manifest
  • before/after task set
  • rollback and owner disposition

已知風險

  • ten-point compliance score can become false precision
  • fixed seven-component topology may not fit a smaller domain harness
  • workspace initialization and validation scripts were not executed
  • paper-derived claims still require local task evidence

立即淘汰

  • requires private-session cookies, automatic login, anti-bot or CAPTCHA bypass
  • sends confidential context, RTL, logs, credentials, license data or tool reports to an external service
  • cannot reproduce failure, rollback state, tool scope and exact artifact readback

public fixture source review → isolated canary → measurable failure/recovery evidence → owner approval → only then package a deterministic domain adapter; public results never prove internal EDA correctness
