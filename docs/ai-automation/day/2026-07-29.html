Evidence-Governed Domain Agent Harness

聚焦高風險工程與 ASIC automation：把設計意圖、驗證意圖、確定性執行包、真實工具證據與 owner approval 串成一條可稽核鏈，而不是投入通用爬蟲或提示工程。

反方觀點

熱門專案的星數、文件自述節省量與平台覆蓋不等於企業採用或可靠性；原生模型能力也可能快速吸收部分框架價值。

催化劑

  • 工具數量增加後，動態發現與最小權限路由比把所有工具塞進上下文更重要
  • 長任務與多代理協作需要 conversation 外的 checkpoint、重試、取消與 readback
  • 企業開始要求 trace、evaluation、sandbox、資料邊界與人類核准能同時成立
  • 模型價格與能力收斂，使 domain evidence contract 成為更持久的差異化資產

領先指標

  • 開源專案是否從 agent demo 轉向 checkpoint、conformance、doctor 與 rollback
  • 工具整合是否改採 runtime discovery、scoped auth 與可撤銷 session
  • evaluation 是否能連回確切輸入、工具呼叫、輸出與失敗分類
  • sandbox 是否提供網路、檔案、credential 與 artifact 的明確政策及 readback
  • 同一 evidence contract 是否能跨至少三個 domain task 重現
什麼會推翻這個 thesis
  • 原生模型平台在不犧牲可攜性下完整吸收 durable state、evaluation 與 policy control
  • 增加 harness 層後沒有降低失敗重現時間或 owner 介入次數
  • context compression 在真實任務上造成關鍵約束遺失且無法由可逆取回機制補救
  • domain workflow 無法產生可機器讀取的工具證據，只剩敘事型報告

輸入與 claim boundary

跨任務 reproducibility、owner interruption、recovery effort、evidence integrity、外部需求訊號

內部效率或 demo 不等於付費需求；EDA claim 仍需核准環境真工具證據。

利基篩選器

  • 高頻或高代價工程痛點，但公開 skill 供給稀疏
  • 模型能力提升後仍需要的 domain schema、oracle、evidence 與 approval
  • 可先用公開 fixture 驗證，之後以 deterministic bundle 進核准環境
  • 能降低失敗重現時間、重複脈絡說明或 owner interruption，且不犧牲 verification integrity

對你工作最有價值的三個假設

  1. RTL／DV Evidence Kernel

    把 requirement、cycle contract、assertion、simulation artifact、review claim 與 owner disposition 串成同一 ledger。

    Canary：公開 toy datapath 的 intent→RTL/SVA→simulation evidence bundle 與獨立 claim audit。
    升級 gate：另一個 worker 可只靠 bundle 重現，且 false-PASS negative test 能被 gate 擋下。

  2. EDA Tool Capability Registry

    把 VCS、Verdi、lint、CDC、synthesis、LEC/ECO 的 capability、preflight、版本與失敗原因型別化。

    Canary：先用 mock adapter 驗證 allowlist、negative authorization、artifact manifest 與 fallback，不連公司工具。
    升級 gate：進核准環境後，真實 tool/version/command/report readback 能對上相同 schema。

  3. Frontend ECO Failure Replay

    前端 ECO 的稀缺價值不是自動改 RTL，而是保存 root cause、變更邊界、等價性預期與 rollback 證據。

    Canary：公開 combinational/sequential toy change 的 before/after cone、test、equivalence expectation 與 rollback trace。
    升級 gate：無 owner approval 不改 source；沒有 LEC/正式等價性 readback 不宣稱 ECO 正確。

分析工具的 authority 邊界

Production：deterministic Python builders、versioned JSON evidence、tests 與 Pages readback

Exploration：Jupyter notebook 僅用於 cohort、trend、niche hypothesis 與圖表探索；結論須回寫受測試的 pipeline

AI：AI 撰寫 thesis／anti-thesis 與決策敘事，但不能覆寫 evidence ledger 或工具結果

IC DESIGN AUTOMATION BLUEPRINT · PROPOSED_REQUIRES_OWNER_APPROVAL · OA_CONTEXT=PARTIAL · NX_CONTEXT=SNAPSHOT_ONLY

IC Design Automation：從環境到驗證的 build-up 路線

把每次 IC 設計變更壓成可恢復的 intent→execution→evidence→decision loop；工程師只需要看變更邊界、最早可信失敗與真正需要裁定的問題。

不可妥協原則

  • 先建 evidence kernel，再考慮自動產生或修改 RTL。
  • AI 可提出 candidate；只有 deterministic gate 與真實工具 readback 能提升 claim。
  • 最快的迭代不是少跑驗證，而是更早得到可定位、可重播的失敗。
  • 把 owner attention 當受限資源，但不得靠隱藏風險或降低 verification integrity 節省。

建議 owner decision

第一個 MVP 選 RTL／DV Evidence Kernel，先完成公開 toy datapath 的五種 false-PASS mutation 與 replay bundle。

替代：若先做 tool registry，環境治理更快，但短期無法證明 verification value。
若暫緩：維持公開 blueprint 與 mock adapter，不進 NX、不改任何產品 RTL。
requires_owner_approval=True

六層 build architecture

ENVIRONMENT PLANE

1. 可重現環境底座

任何核准 worker 都能從乾淨 checkout，以單一入口重現同一個 stage。

  • repo-owned control plane；流程狀態不只存在 agent 對話
  • tool capability registry：版本、license/preflight、輸入輸出、side effect、timeout 與 fallback
  • content-addressed artifact store、固定 seed、相對路徑、原子寫入、idempotent rerun

核心產物：tool_capabilities.json run_manifest.json environment_readback.json

Promotion proof：clean-checkout replay、版本/readback 相符、缺工具或權限時 fail closed

降低認知負載：工程師不再反覆追問『跑的是哪一版、哪個工具、哪個目錄』。

方法來源：MCP Reference Servers、LangGraph、Agentic Harness Engineering

ITERATION PLANE

2. 加速迭代與失敗重播

每次變更先跑最便宜且足以推翻 claim 的 gate，再逐級升級。

  • diff impact map：變更 requirement/module/interface/assertion 對應受影響測試與 EDA stage
  • fast/medium/signoff 三速 queue、checkpoint/resume、cache validity 與 duplicate-run suppression
  • 保存 first failing seed、最早 divergence、輸入版本、工具版本與最小 replay command

核心產物：impact_map.json gate_plan.json failure_replay.json

Promotion proof：另一個 worker 可重現同一最早失敗；cache miss/hit 理由可讀回

降低認知負載：把『重跑整包再看海量 log』改成『先看最小失敗與受影響 cone』。

方法來源：LangGraph、systemverilog-waveform-debug、rtl-equivalence-checker

ACCURACY PLANE

3. 準確度與 false-PASS 防線

準確度先定義成 claim 可追溯、oracle 可重現、弱 gate 不冒充強 gate。

  • design intent／verification intent schema：width、signedness、fixed-point、cycle、reset、protocol、non-goal
  • requirement→assertion/test/coverage/evidence traceability；每個 UNKNOWN 保留 owner/next check
  • negative fixture、mutation、vacuity、X/unknown、boundary 與 stale-golden 檢查

核心產物：design_intent.yaml verification_intent.yaml claim_ledger.jsonl

Promotion proof：故意植入的 false PASS 能被擋下；每個 PASS 可回到 oracle、輸入、版本與 exact gate

降低認知負載：工程師不用重讀整份報告，只審未證實假設、衝突與 promotion decision。

方法來源：spec-planner、rtl-p3-uarch-policy、rtl-quality-reviewer

ATTENTION PLANE

4. 認知負載與 owner decision surface

每次只呈現三件事：改了什麼、最早可信失敗在哪、哪個問題必須由 owner 決定。

  • resumable checkpoint：intent、assumption、evidence、failure、decision、exact next action
  • 相同結果自動折疊；新風險、authority conflict、irreversible action 才打斷 owner
  • 把零散問題批次化成 recommendation／alternatives／consequences／default decision packet

核心產物：checkpoint.json decision_packet.md owner_disposition.json

Promotion proof：handoff 不需重講背景；可量測 interruption、重複提問、恢復工時與 owner correction

降低認知負載：AI 承接記憶與可逆執行，人保留高價值架構判斷與不可逆裁定。

方法來源：Agentic Harness Engineering、Headroom、Langfuse

EDA PLANE

5. EDA 方法論與 typed evidence adapter

每個 EDA stage 只回答自己有權回答的問題，輸出 typed evidence 而非自然語言 PASS。

  • adapter 共通 contract：tool/version/command/input hash/corner/seed/status/report hash/line/quote
  • lint、compile/elaboration、simulation、CDC/RDC、formal、synthesis、LEC 分開建 authority 與失敗型別
  • 先做 mock/conformance adapter；進 NX 後再用核准報告校準 parser 與 negative fixture

核心產物：eda_capabilities.json evidence_manifest.json gate_result.json

Promotion proof：unknown format、空報告、零 compared points、缺 corner/version 或 parser ambiguity 一律不升級 claim

降低認知負載：把不同工具 log 統一成可排序 failure taxonomy，但保留原始 report provenance。

方法來源：review-rtl-architecture、hw-cdc、prepare-rtl-for-synth、equivalence-check

VERIFICATION PLANE

6. Verification factory

把單點 testbench 經驗轉成可跨 block 重用的 oracle、observer、assertion、coverage 與 replay pattern。

  • Reference Model 是 expected 唯一來源；Scoreboard 只負責配對與 bit-true compare
  • cycle/reset/valid-ready/backpressure contract 加上多節點 observer，找 earliest divergence
  • directed boundary、constrained-random、assertion/formal、coverage hole、ECO equivalence 各自有 exit gate

核心產物：verification_plan.yaml traceability_matrix.json coverage_ledger.json

Promotion proof：正常、邊界、故障注入與 stale/misaligned oracle 都能得到預期 verdict；重跑結果一致

降低認知負載：debug 從『最後輸出錯了』縮成『哪個 contract、哪個節點、哪個 cycle 首次偏離』。

方法來源：formal-verification、systemverilog-waveform-debug、equivalence-check
