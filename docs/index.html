二、沒人注意到但做得起來的利基

利基的定義是可驗證的量：若這個領域的任務分佈跟全體一樣，這種能力「應該」有幾件， 實際卻只有幾件。比值越低＝結構性缺席越明顯。再疊上該領域的動能， 就能分出「需求在長、能力卻缺席」與「本來就不該做」。

資料與限制

  • 樣本僅涵蓋公開到 GitHub 的 skill，系統性低估法務、醫療、金融、IC 設計的真實採用率。
  • 時間軸用 repo 建立時間，代表「這個 skill 所在的 repo 何時建立」，不是 skill 何時被寫出、更不是何時被使用。
  • 最近期的數字會偏低：新 repo 尚未被搜尋索引完全收錄，也還沒累積 star。近 1–2 期的下滑不要當成退燒。
  • star 屬於 repo 不屬於 skill；大型專案順手附的 skill 會繼承該專案的 star。
  • 分類由 LLM 標註，小樣本（n<30）的比例數字不穩定。
